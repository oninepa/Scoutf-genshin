# 12 배포 · 업데이트 · 보호

## 원칙
- 사용자 PC/브라우저에 간 것은 100% 숨길 수 없다. 진짜 중요한 것은 **보내지 않는다**.
- 개발 저장소(Private)와 배포물(공개)을 분리한다. 배포물은 "넣을 것만 지정"해서 새로 만든다.

## 1. 저장소 구성
- 개발 저장소: **Private**. 이 스타터 전체(docs, 프롬프트, 메모 포함)가 여기 있다.
- 배포: 공개 저장소 또는 호스팅에는 `release-out/` 내용만 올린다.

## 2. 서버로 뺄 것 (사용자에게 안 보내는 것)
- [ ] API 키
- [ ] 프롬프트, 핵심 로직/노하우
- [ ] 광고 설정, 로그인/사용량 제한, 유료 기능 판별
- [ ] 바뀔 수 있는 문구/설정 (서버에서 내려주면 패치 없이 변경 가능)
서버 후보: Cloudflare Workers, Vercel/Netlify Functions 등 (무료 구간 있음). 프로그램은 서버에 요청만 보낸다.

## 3. 서버로 못 뺀 것
- 난독화/압축은 캐주얼한 사람만 막는 수준이다. 중요한 것은 2번으로 옮긴다.

## 4. 업데이트 방식
- **웹앱/PWA**: 호스팅에 새로 올리면 모두 자동 반영. 서비스워커의 캐시 버전을 올려야 한다.
- **설치형 프로그램**: 실행 시 `version.json`을 확인해 새 버전이 있으면 안내/다운로드.
- 한글 추가, 광고, 문구 변경은 가능하면 서버 설정으로 처리해 패치 배포를 없앤다.

## 5. 배포 절차
1. `VERSION` 파일의 버전을 올린다.
2. `release.allow`에 넣을 것만 적혀 있는지 확인한다.
3. `tools\build-release.bat` 실행 → 검사 3개 통과 확인.
4. `release-out/` 내용만 호스팅/공개 저장소에 올린다.
5. STATE.md와 DECISIONS.md에 배포 내용을 기록한다.

## 6. 배포 전 체크리스트
- [ ] build-release 검사 통과
- [ ] release-out에서 실제 앱을 열어 동작 확인
- [ ] 브라우저 개발자도구(F12)에서 소스에 프롬프트/키가 안 보이는지 확인
- [ ] licenses.txt에 사용한 오픈소스/데이터 출처 표기 (라이선스상 요구되는 경우가 많다. 지우면 위반될 수 있다)
- [ ] 개인정보 수집이 있으면 개인정보 안내 문구
