# 13 프롬프트 모음 (복사해서 붙여 넣기)
> [대괄호]는 내 상황에 맞게 바꾼다.

## 전체 순서
1. 아이디어 정리 (Opus 또는 무료 AI) → 프롬프트 1
2. 문서 채우기 (Sonnet) → 프롬프트 2
3. 프로젝트 폴더 만들기 + 스타터 복사 + 채운 문서 넣기 + GitHub 올리기(tools\first-setup.bat)
4. 에이전트가 읽고 이해했는지 확인 → 프롬프트 3
5. 태스크 하나씩 구현 → 프롬프트 4 (반복)
6. 오류 검사 보고서 → 프롬프트 5, 보고서 확인 후 수정 → 프롬프트 6
7. 배포 → 프롬프트 7

---

## 프롬프트 1: 아이디어 대화 정리 (Opus)
아래 대화는 [프로젝트 이름]에 대한 아이디어 논의야. 다음 5가지로 정리해 줘.
1. 확정된 결정 (이유 포함)
2. 서로 모순되거나 중간에 말이 바뀐 부분
3. 아직 안 정해진 것 (내가 답해야 할 질문 목록)
4. 이번 첫 버전(MVP)에 넣을 기능 5개 이내 추천, 나중으로 미룰 기능 목록
5. 위험한 부분 (기술, 비용, 저작권/약관, 개인정보)
대화에 없는 내용은 지어내지 마. 없으면 "미정"이라고 써.
[대화 붙여 넣기]

## 프롬프트 2: 스타터 문서 채우기 (Sonnet)
아래는 (A) 아이디어 정리본, (B) 빈 문서 틀(PROJECT.md, docs/01~05)이야.
정리본 내용으로 각 문서를 채워서 파일별로 출력해. 각 파일은 "### 파일경로" 제목 아래 코드블록으로 줘.
규칙:
- 정리본에 없는 내용은 지어내지 말고 "TODO(질문): ..."로 남겨.
- 02-mvp.md는 넣을 것 5개 이내, 안 넣을 것 목록을 반드시 채워.
- 05-tasks.md는 한 태스크 10~30분, 완료 기준 포함, 순서대로.
- 03-architecture.md의 기술 스택은 [내 PC 사양/무료 위주/웹앱·PWA 등 조건]에 맞춰.
- 마지막에 내가 결정해야 할 TODO 질문만 모아서 알려 줘.
(A) [정리본]
(B) [빈 문서들]

## 프롬프트 3: 에이전트 첫 확인 (코드 쓰기 전)
CLAUDE.md, INDEX.md, PROJECT.md, STATE.md, docs/10-rules.md, docs/DECISIONS.md를 읽어.
아무것도 만들거나 수정하지 말고, 이 프로젝트가 뭔지, MVP 범위, 기술 스택, 첫 태스크를 5줄로 요약해.
문서끼리 안 맞거나 빠진 부분이 있으면 따로 알려 줘.

## 프롬프트 4: 태스크 구현 (반복)
docs/05-tasks.md의 [번호]번 태스크만 해. 시작 전에 바꿀 파일과 방법을 먼저 말해 줘.
끝나면 STATE.md를 갱신하고, 커밋 메시지를 제안해. 다른 태스크나 새 기능은 건드리지 마.

## 프롬프트 5: 오류 검사 보고서 (수정 금지)
프로젝트 전체를 읽고 오류 검사 보고서만 써. 파일은 수정하지 마.
확인할 것: 실행 시 오류, 깨진 링크/경로, 문서와 코드가 안 맞는 부분, 빠진 예외 처리, 키/비밀값 노출, 02-mvp 범위를 벗어난 기능.
심각도(높음/중간/낮음)별로, 파일명과 위치, 원인, 고치는 방법을 표로 정리해.

## 프롬프트 6: 보고서 기반 수정
위 보고서의 [높음] 항목부터 하나씩 고쳐. 한 항목 고칠 때마다 무엇을 바꿨는지 말하고 나한테 확인받아.
같은 항목을 2번 고쳐도 안 되면 멈추고 알려 줘.

## 프롬프트 7: 배포
docs/12-release.md와 docs/08-security.md를 읽고 그 순서대로 배포 준비를 해.
1) release.allow에 넣을 것만 남았는지 확인 2) VERSION 올리기 3) tools\build-release.bat 실행 결과 확인
검사가 실패하면 원인을 고치되, 서버로 옮겨야 할 것(키, 프롬프트)은 옮기는 방법을 먼저 제안해.
마지막에 배포 전 체크리스트 결과를 표로 보고해.
